## Context

参见 [proposal.md](./proposal.md) 的 Why。当前上传控制器已将三个行政区参数声明为 `@RequestParam(required = false)`，但 Swagger 仍把 cityCode、districtCode 标记为必填，服务实现也会拒绝二者的 null 或空白值。provinceCode 已具备“null 转空字符串、非 null 去首尾空白”的保存行为，三个字段的处理方式尚未统一。

本次行为契约见 [specs/image-upload/spec.md](./specs/image-upload/spec.md)。数据仍写入 MongoDB `image_metadata`，图片仍写入 GridFS；现有服务接口参数顺序、实体字段、列表筛选和更新接口均可保持不变。

## Goals / Non-Goals

**Goals:**

- 在控制器、Swagger 与服务层之间建立一致的“省、市、区县均可选”契约。
- 在唯一的持久化入口统一规范化三个字段，保证本次变更后新建记录中的值均不为 null。
- 用契约测试和服务单元测试覆盖缺失、空白、任意组合及非标准代码，防止重新引入必填或格式校验。

**Non-Goals:**

- 不改变上传服务方法签名、ImageMetadata 数据结构或 MongoDB 集合结构。
- 不增加行政区代码格式、长度、层级或组合合法性校验。
- 不为列表接口增加“查询空行政区记录”的特殊语法，也不改变现有精确筛选逻辑。
- 不开放更新接口修改或补录行政区字段，不批量清洗或迁移历史记录。

## Decisions

### 1. 在服务持久化入口统一规范化三个行政区字段

上传服务在构造 ImageMetadata 时，对 provinceCode、cityCode、districtCode 使用同一规范化规则：null、空字符串和纯空白转为 `""`，其余值调用 `trim()`。同时删除 cityCode、districtCode 的非空拒绝分支，保留 file 与 title 的现有校验。

选择服务层作为最终规范化边界，是因为控制器之外的调用也可能直接使用 ImageService；仅依赖 Spring MVC 参数绑定无法保证所有入口写入一致值。可考虑在控制器中转换，但这会使直接调用服务时仍可能保存 null，因此不采用。服务接口签名无需变更，降低调用方改动范围。

### 2. HTTP 可选性由请求绑定和 Swagger 同时表达

三个行政区参数继续使用 `@RequestParam(required = false)`；移除 cityCode、districtCode 上 `@ApiParam(required = true)`，并统一说明缺失或空白将保存为空字符串。400 响应说明只保留文件或标题为空的情况。

选择修改现有注解而不是新增 multipart 请求 DTO，是因为该项目上传、更新接口均采用独立 `@RequestParam`，本次没有引入结构化校验的需求。维持现有接口形态可避免前端请求格式变化。

### 3. 仅调整上传路径，其他接口保持现状

列表接口继续忽略空白筛选值并对非空值精确匹配；更新接口继续不声明三个行政区参数；详情和删除沿用现有逻辑。历史记录若缺少字段或字段为 null，读取时保持原值，不在本次变更中自动补写。

选择不为列表增加空值查询能力，是为了避免把“未提供筛选条件”和“筛选空行政区”混为一谈。选择不允许更新补录，是为了维持已批准的“行政区字段创建后不可修改”契约。

### 4. 用现有测试层级验证契约和持久化行为

先修改测试并确认在旧实现上失败：服务单元测试覆盖三个字段全部缺失、空白、部分提供和非标准值；Swagger 契约测试断言三个参数均为非必填且说明一致。实现后运行相关测试，再运行完整 Maven 测试。前端联调文档同步给出全部省略和部分提供的请求示例。

不新增依赖或新的集成测试基础设施，继续使用 Mockito、Spring Boot 测试和现有 Swagger JSON 断言，减少与业务无关的变动。

## Risks / Trade-offs

- [此前因 cityCode 或 districtCode 为空而返回 400 的请求将变为成功] → 在 Swagger 和联调文档明确这是兼容性放宽，并用契约测试锁定新行为。
- [允许任意组合会产生行政区信息不完整的记录] → 新记录始终写入非 null 字符串，前端按空字符串展示缺失信息；不在后端推断层级值。
- [历史记录仍可能缺字段或为 null，与新记录的空字符串表现不同] → 保持现有兼容读取逻辑，不进行隐式写回；本次仅保证新建记录。
- [空白筛选被忽略，无法专门检索行政区为空的记录] → 明确记录为既定列表语义，不扩展查询协议。
- [行政区字段不可更新，上传后无法补录空值] → 在联调文档突出创建后不可修改，调用方需要在首次上传时提供希望长期保存的值。

## Migration Plan

1. 先提交会在旧实现上失败的服务测试和 Swagger 契约测试，确认失败原因与本变更一致。
2. 修改上传服务校验与规范化逻辑，并更新控制器 Swagger 注解。
3. 更新前端联调文档，运行相关测试和完整 Maven 测试，再执行 OpenSpec 严格校验。
4. 正常发布应用；无需数据库脚本、停机迁移或依赖升级。

若需要回滚，恢复原有 cityCode、districtCode 非空校验及 Swagger 必填声明即可。回滚前已写入空字符串的记录继续按历史兼容逻辑读取，无需删除或改写。
